# 랜딩페이지 Section 2 — 루프카드→TOLA Data→위젯 통합 인터랙션 설계

**날짜:** 2026-07-15
**관련 브랜치:** feature/DV-90-landing-page
**Figma:** https://www.figma.com/design/Av6wndsR8wpp1w7BIduyyz/KLLJS?node-id=1912-24559 (카드 레이아웃), node-id=1912-24648 (TOLA Data·5개 위젯 배치, Frame 8: `1912:24963`)

## 배경

기존에 커밋된 Section 2(타이틀+루프카드, `whileInView` 등장)를 확장한다. 루프카드가 스크롤에 따라 제자리에서 축소되며 TOLA Data로 디졸브되고, 이어서 5개 위젯이 상승 등장하는 인터랙션을 추가한다. 이전 시도에서 여러 버그를 겪고 원인을 찾은 뒤 롤백했고, 이번 스펙은 그 교훈을 처음부터 반영한다.

## 범위

- **포함:** 등장(Hero 크로스페이드) → 타이틀+루프카드 유지 → 루프카드 제자리 축소 → TOLA Data 디졸브 → 5개 위젯 상승 등장까지 하나의 sticky 구간
- **제외:** 6개 위젯(TOLA Data 포함) 내부의 실제 차트/그래프 — 이번에도 제목+카드 틀만 있는 자리표시자
- **제외:** 타이틀 재등장 — 한 번 사라지면 계속 사라진 상태 유지 (이전 설계에서 있었으나 제외하기로 확정)

## 동작

Hero가 sticky에서 풀려 화면 밖으로 스크롤되어 나가는 구간과 겹쳐 크로스페이드로 등장한다(기존 Section 2와 동일, `ScrollHero`의 exit와 같은 패턴).

이후 하나의 sticky 고정 구간 안에서 순서대로:

1. **유지**: 타이틀 + 루프카드(6장 이미지, 우→좌 무한 루프) 그대로 보임
2. **타이틀 페이드아웃**
3. **루프카드 축소**: 루프카드가 **TOLA Data와 동일한 위치·크기(고정)에서 scale만으로** 커진 상태(예: 1.6배)에서 1배로 축소 — 위치는 전혀 움직이지 않고 중앙 기준으로만 작아진다. 루프는 축소 중에도 계속 돈다.
4. **디졸브**: 루프카드 → TOLA Data. **루프카드와 TOLA Data는 완전히 같은 scale 곡선을 공유**해서 축소 시작점이 서로 어긋나지 않는다. 디졸브 구간은 축소가 끝나가는 구간과 겹쳐서 자연스럽게 이어진다. **디졸브가 끝난 시점부터는 루프카드가 오퍼시티 0으로 완전히 고정되어야 하며, 이후 5개 위젯이 등장하는 동안을 포함해 스크롤이 끝날 때까지 다시는 보이지 않아야 한다.**
5. **5개 위젯 상승 등장**: Best Flow, Time Years Heat Map, Gender Years View, Live Viewer Graph, Average View Time이 각자 Figma 실측 좌표(TOLA Data를 둘러싸는 배치)에서 아래로 조금 내려간 채 숨어있다가, 제자리로 올라오며 페이드인. 전부 같은 타이밍에 동시에 올라온다.
6. **유지**로 마무리 — 이 시점에도 루프카드는 계속 보이지 않는다.

## 반응형

- **데스크탑(`lg`, 1280px 이상)**: 위 스크롤 인터랙션 전체 적용
- **태블릿/모바일(`lg` 미만)·`prefers-reduced-motion`**: 타이틀 + 루프카드(정적 또는 계속 루프) 아래로 TOLA Data + 5개 위젯이 세로 1열로 쌓여 각자 뷰포트 진입 시 1회성 페이드업(`whileInView`) — 기존 Section 2 모바일 패턴과 동일

## 구현상 반드시 지킬 것 (이전 시행착오에서 확인된 버그 원인)

1. **sticky wrapper는 `h-dvh` 사용, `min-h-dvh` 금지.** `min-h-dvh` + flex 자식이 일반 흐름 엘리먼트면, 자식이 뷰포트보다 클 때 sticky wrapper 자체가 늘어나 버려서 sticky 계산이 한 화면 기준을 벗어난다.
2. **등장 트랜지션(entrance opacity/y)은 sticky 엘리먼트 자신이 아니라 자식에 적용.** sticky 엘리먼트 자체에 transform을 걸면 sticky 해제 시점 계산이 불안정해질 수 있다.
3. **같은 시각 요소에서 opacity와 scale(또는 다른 transform)을 한 엘리먼트의 style에 같이 두지 않는다.** 실제로 겪은 버그: 한 엘리먼트에 `{ scale, opacity }`를 같이 넣었더니 scale은 스크롤에 맞춰 실시간으로 갱신되는데 opacity만 갱신되지 않고 고정값(1)으로 멈춰있었다(devtools로 확인). **opacity 담당 엘리먼트(부모)와 scale 담당 엘리먼트(자식)를 분리**해서 각각 단일 책임만 갖게 한다.
4. **`sectionRef`·`useScroll`은 데스크탑 전용 하위 컴포넌트 안에 둔다** (`DesktopSection2`처럼) — `ScrollHero`와 같은 이유로, 반응형 분기 컴포넌트가 언마운트/재마운트될 때마다 새로 구독되어야 리사이즈 후에도 스크롤에 정상 반응한다.
5. 위젯 자리표시자는 기본 스타일(흰 배경 카드, `bg-bg-secondary`)을 쓴다 — 이전에 진단용으로 넣었던 파란 배경(`primary-brand-solid`)은 디버깅용이었을 뿐 최종 디자인이 아니다.
